# Contributing to Chumbow Lab

Thank you for taking an interest in the practical resources and prototypes in this portfolio.

## What kind of contributions are useful?

- Clear bug reports with steps to reproduce.
- Documentation corrections and accessibility improvements.
- Suggestions grounded in a real workflow or user need.
- Small, focused improvements that preserve the project's stated scope.
- Reusable templates that do not expose private or copyrighted material.

## Before proposing a change

1. Read the relevant project README and its limitations.
2. Check existing issues and discussions to avoid duplication.
3. Describe the problem and the expected outcome.
4. Keep changes focused and explain any trade-offs.
5. Never include passwords, access tokens, private client information or confidential records.

## For code changes

- Prefer readable, maintainable changes over unnecessary dependencies.
- Test the affected workflow in a current browser or the documented environment.
- Include steps to reproduce and verify the change.
- Update documentation when behaviour, setup or limitations change.
- Do not claim a test passed unless it was actually run.

## For templates and documentation

- Use plain language and practical examples.
- Mark illustrative examples clearly.
- Avoid legal, security or compliance claims that have not been verified.
- Explain where a template must be adapted to an organisation's own policies.

## Licensing

Unless a specific project or file includes a licence, do not assume that it is licensed for unrestricted reuse. Ask before redistributing or incorporating material into another product.
